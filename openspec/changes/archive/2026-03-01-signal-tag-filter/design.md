## Context

總表頁面（HomePage）透過 `LOAD_ALL_LIMIT: 5000` 載入全部 ~2700 支股票到瀏覽器記憶體。每支股票包含 5 個訊號陣列：`chip_signals`、`technical_signals`、`fundamental_signals`、`recent_events`、`cb_signals`，各含 `{ name, triggered, score, description }` 結構。目前只有排序和權重調整功能，無訊號篩選。

## Goals / Non-Goals

**Goals:**
- 使用者可按訊號名稱組合篩選股票（AND 邏輯）
- 訊號標籤按分類展示，顯示觸發股票數
- 即時篩選，無需 API 往返

**Non-Goals:**
- 不改後端 API（資料已完整載入前端）
- 不做 OR 邏輯或進階查詢語法
- 不做篩選條件的 URL 持久化（首版不做）
- 不做訊號間衝突的自動偵測提示

## Decisions

### 1. 純前端篩選，不加後端參數

**選擇**：在前端 `useMemo` 過濾已載入的 stocks 陣列

**替代方案**：新增 API `?signals=多頭排列,大戶急買` 參數，在 PostgreSQL JSON 欄位查詢

**理由**：前端已持有全部 ~2700 支股票的完整訊號資料。2700 × ~10 signals 的 in-memory 過濾 sub-ms 完成，不需引入 API 複雜度。

### 2. 訊號目錄用靜態常數，不從資料動態推導

**選擇**：建立 `signalCatalog.ts` 靜態定義所有 67 個訊號名稱與分類

**替代方案**：從已載入的 stocks 資料中動態收集所有出現過的訊號名稱

**理由**：動態推導會漏掉當下沒有任何股票觸發的訊號（用戶看不到、無法選擇）。靜態目錄確保完整性，且訊號集合變動頻率極低（數月才新增一次）。

### 3. 可展開面板 UI，預設收合

**選擇**：獨立的可展開面板組件，放在 WeightController 和表格之間，預設收合

**理由**：67 個標籤展開後佔用大量空間，預設收合避免干擾不需要篩選的使用者。收合時若有已選標籤，以 badge 數字提示。

### 4. 標籤顏色按訊號分數正負區分

**選擇**：正分訊號（買入）用綠色系，負分訊號（風險）用紅色系

**替代方案**：按分類用不同顏色（藍、綠、紫等）

**理由**：正/負分對投資決策更直覺，且與既有 tooltip 中的訊號顏色一致（green-400 / red-400）。

## Risks / Trade-offs

- **訊號名稱不一致** → 靜態目錄的名稱必須與後端 `ChipSignal.name` 完全一致。建立時從 `SIGNAL_DEFINITIONS.md` 和後端程式碼交叉比對。
- **訊號新增時需同步更新目錄** → 風險低（訊號變更頻率低），未來可考慮從 API 提供訊號清單端點。
- **大量標籤的 UI 空間** → 用分類摺疊 + flex-wrap 控制，每類一行 label + 標籤列。
